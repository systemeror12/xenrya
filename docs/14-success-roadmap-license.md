# 14. Success Criteria, Future Roadmap & License

# Success Criteria

## Primary Criterion

> I voluntarily keep Xenrya running during normal development because it improves my desktop experience rather than because I am testing it.

## Long-Term Product Success

Xenrya should:
- Become regularly useful for developer awareness.
- Feel significantly more alive than a traditional notification app.
- Remain non-intrusive during long work sessions.
- Remain resource-efficient enough to run all day.
- Allow substantial customization without source-code changes.
- Help users understand important activity across projects quickly.
- Encourage community-created characters/plugins.
- Remain enjoyable even if it stays niche.

## Warning Signs

- Frequent shutdown because Xenrya is distracting.
- Most notifications disabled immediately.
- Noticeable CPU/RAM/GPU overhead.
- Character becomes irrelevant decoration.
- AI becomes required.
- Basic configuration requires excessive troubleshooting.
- Extension creation is too difficult.
- Xenrya duplicates coding agents.
- GitHub/GitLab awareness becomes untrustworthy.

## Open-Source Success Signals

Potential positive indicators:
- External contributors
- Community character packs
- Third-party integrations
- Useful bug reports
- Maintained distro packages
- Custom forks/setups
- Good contributor docs

# Future Roadmap

## Approved But Uncommitted

- Pomodoro / focus
- Task management
- System monitoring
- Music awareness
- CPU/RAM widgets
- Natural-language computer control
- AI chat
- Coding-assistant integration
- Autonomous actions
- Windows support
- Battery-aware optimization
- Packaged character format
- Community plugin/character registry
- Flatpak
- AppImage if demand exists

## Windows

Possible future platform if motivation/community demand exists.

Linux-first architecture should not be constrained prematurely by Windows.

## AI Roadmap

Preferred order:

```text
1. Contextual dialogue
2. Developer activity summaries
3. PR/MR summaries
4. Explain failures/events
5. AI chat
6. Tool/harness integration
7. Permissioned shell execution
8. More autonomous actions
```

AI begins advisory/contextual and becomes agentic only much later.

## Coding-Agent Relationship

Integrate with coding agents rather than replace them.

Possible future events:
- Agent started
- Agent finished
- Agent needs input
- Tests running
- PR created
- Review requested
- Tool failed

## Desktop Integration Roadmap

```text
Generic Wayland behavior
        ↓
Hyprland awareness
        ↓
Desktop shell integration
        ↓
Caelestia integration if still relevant
```

Caelestia is never a hard dependency.

## Community Ecosystem

Potential later components:
- Character Gallery
- Plugin Registry
- Theme/Sound Packs
- Pack Validator
- Developer SDK
- Example plugins
- Character templates

Only after APIs stabilize.

## Contribution Philosophy

Contributions are welcome.

Examples:
- Bug fixes
- Character support
- Integrations
- Documentation

Major changes require maintainer approval:
- Architecture shifts
- Security-model changes
- Product-direction changes
- Core permission changes

## Public Roadmap States

Use:
- Committed
- Planned
- Exploring
- Not planned

Roadmap items are not automatically promises.

# North Star

> **Xenrya should become a customizable, expressive developer companion that stays aware of meaningful development activity, feels naturally integrated into the desktop, and can grow into deeper automation and AI capabilities without sacrificing user control, privacy, performance, or personality.**
