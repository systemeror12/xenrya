# Additional local-only Hatsune Miku VRM options

**Research date:** 2026-09-20  
**Scope:** creator-published Hatsune Miku VRM/VRoid models that could be used as a private, noncommercial, local-only Xenrya character pack. No model files were downloaded, opened, or uploaded. The links below are source and preview pages, not bundled dependencies.

## Conclusion

Daily-style Miku is still the best baseline for a first expressive VRM experiment because its creator publishes unusually concrete facial data: VRM 0.x, 44 MMD-compatible blendshapes, 21 facial-expression animations, lip sync, eye tracking, and MToon. Its page permits modification and personal use, but the exact VN3 terms are inside the download and were not checked here.

The strongest additional candidates are:

1. **Tea Chami Miku** — best practical alternative. It has free VRM 0.0 and 1.0 files, explicit modification and game/app embedding permission, and a creator-published VN3 terms link. Expression counts are not published.
2. **Yukihane Miku** — best expression-rich alternative. The free package advertises about 30 expression shape keys, lip sync, and 10 hand-sign plus 10 action-menu expressions. It is more Unity/VRChat-oriented and the public summary does not explicitly grant arbitrary model modification.
3. **rurune Miku** — strongest modern-looking lightweight alternative if the free plain VRM is sufficient. Modification and format conversion are expressly allowed, but the creator does not publish an expression count and the advertised package name conflicts with the VRoid Hub format metadata.
4. **Imayahaya Miku** — permissive free fallback with VRM 0.0, editable VRoid data, and explicit modification permission. It has less integration and expression information than Daily.
5. **Benjamin Miku** — a technically useful fallback because the creator explicitly permits use in games and applications that read VRM/VRoid files, but it is older and has a doll-like presentation.

The models below remain **local-only** for Xenrya. The model creator's permission is only one layer: every Miku derivative also remains subject to Crypton Future Media's [Piapro Character License](https://piapro.jp/license/pcl/summary) and [character guidelines](https://piapro.jp/license/character_guideline). Xenrya should not distribute any of these models, altered exports, rendered sprite caches, screenshots, or public demos.

## Candidate details

### 1. Tea Chami Miku — recommended additional candidate

**Creator and source.** Tea Chami (`茶味`, BOOTH account `cha-aji`; the page also lists `@nao_0902`) publishes the free [BOOTH package](https://booth.pm/ja/items/6230295). The creator's [VRoid Hub page](https://hub.vroid.com/en/characters/6181240482961346861/models/6658663990429229277) is the preview. The model is explicitly described as a Hatsune Miku fan model.

**Format and appearance.** The package contains a `.vroid` source and both `vrm0.0.vrm` and `vrm1.0.vrm`; the BOOTH page reports about 49,956 triangles, 21 materials, and MToon. Neither page states a blendshape count or named expression set. The VRoid Hub metadata identifies its preview as VRM 0.0.

**Terms.** The BOOTH page says:

- personal VRSNS use, modification, and embedding in games and applications are allowed;
- commercial use is allowed by the creator only with credit, while noncommercial AI use is allowed;
- self-claiming authorship, religious/political use, and improper conduct are prohibited;
- redistribution of the original or modified data is prohibited, including models that use the data;
- credit is not required for ordinary use in the VRoid Hub metadata, but the BOOTH terms require credit for commercial use and the creator asks for the `#茶味式　初音ミク` / `#茶味のお店` tags on public posts.

The page links [Japanese](https://drive.google.com/file/d/1c2xvHNaiqr1aG30fXkjE8MiDLAvnbw5D/view?usp=drive_link) and [English](https://drive.google.com/file/d/1sSnjkIcMymL6VAq3fzNFA1kHO2SU3Sbi/view?usp=drive_link) VN3 terms. The full VN3 clauses were not independently checked. For Xenrya, apply the stricter reading: keep the pack private, retain creator/PCL credit in a local `NOTICE.md`, and do not redistribute or publicly display it.

**Xenrya fit.** This is the strongest additional candidate because “game or application embedding” is written into the creator's terms and both VRM generations are offered. Xenrya still needs a VRM renderer/bridge, expression mapping, and a safe external character directory. Use the VRM 0.0 file first if the chosen loader has better 0.x support. Do not turn generated PNGs, shader caches, or converted files into repository fixtures.

### 2. Yukihane Miku — expression-rich but setup-heavy

**Creator and source.** Yukihane / 雪羽明社 publishes the [free VRC+VRM BOOTH package](https://booth.pm/ja/items/7428125). The creator's [official introduction video](https://www.youtube.com/watch?v=nPOEEp5uoHY) is the clearest public visual preview located. No stable public VRoid Hub model page was found.

**Format and expressions.** The free package contains a Unity package, PNG assets, and a VRM. The page reports 34,788 triangles for the normal model and 37,390 for the swimsuit model, about 30 expression shape keys, lip sync, PhysBones, 10 hand-sign expressions, and 10 action-menu expressions. The page does not state whether the free VRM is 0.x or 1.0.

**Terms.** The page says the model and parts may not be redistributed, shared, uploaded publicly in a cloneable state, or placed on a pedestal. Public VRChat avatar upload is prohibited. R18 use and commercial use are prohibited. Video and live-stream use is allowed with credit; advertising revenue is allowed. A [VN3 Japanese terms document](https://drive.google.com/file/d/11YzxR-8bMu2d79pGwh-Vgy1qen3ziHus/view?usp=sharing) and [English terms document](https://drive.google.com/file/d/11YGh71pdeOL4sTjUTAdN4_j41f7uOSPv/view?usp=sharing) are linked. The public BOOTH summary does not explicitly say whether the model itself may be modified, so do not assume that it can be edited for Xenrya until the terms are read and, if necessary, the creator confirms it.

**Xenrya fit.** It is the best alternative if visible expression breadth matters more than a small dependency footprint. However, the Unity/VRC package is not a drop-in Qt/QML asset, and the public restrictions mean Xenrya must keep it private and avoid using the package as a test fixture. Expression extraction or conversion could itself be a modification, so resolve that permission before implementing a converter.

### 3. rurune Miku — modern free VRM with a format discrepancy

**Creator and source.** rurune / みずのと屋 publishes the free [BOOTH package](https://booth.pm/ja/items/7253804) and [VRoid Hub preview](https://hub.vroid.com/en/characters/7686461039738135583/models/2249309935766221861).

**Format and expressions.** The free download is named `Miku_free_VRM1.1.zip`. However, the VRoid Hub metadata for the corresponding free preview says `VRM 0.0`; the paid-upgrade description says the improved VRM 1.1 had better spring-bone settings and Perfect Sync. The free model's blendshape/expression count is not published. The former paid editable/Perfect-Sync version was discontinued after its Piapro-link term ended on 2026-08-20, with no planned resale.

**Terms.** The creator explicitly allows modification and format conversion. Resale, redistribution, reupload, AI use, and NFT use are prohibited. VRoid Hub marks avatar use and alterations allowed, violence/sexual use disallowed, corporate and individual commercial use disallowed, redistribution disallowed, and attribution not required. The BOOTH page also says to follow Crypton's Miku guidelines. For Xenrya, public display and public upload are unnecessary; treat the model as private and noncommercial.

**Xenrya fit.** Good if the visual style is preferred and the plain free VRM has enough facial keys. Before writing an adapter, manually verify the actual file's VRM generation and expression list; the source pages disagree on the version label. The old paid Perfect-Sync build should not be treated as available merely because the page still describes it.

### 4. Imayahaya Miku — permissive free fallback

**Creator and source.** Imayahaya / イマはや publishes the [free BOOTH package](https://booth.pm/ja/items/5329907) with `.vroid`, VRM, and VRM+FBX choices. The [VRoid Hub preview](https://hub.vroid.com/en/characters/3305084689378069637/models/1428526081348771466) reports VRM 0.0. The VRM/FBX and larger multi-data set include the headphone version; the page also mentions a brighter-hair variant.

**Terms.** Modification, commercial use, and corporate use are allowed by the creator; redistribution, resale, and self-claiming authorship are prohibited. Credit is not required, although the creator appreciates it. The page says the terms must be read together with Crypton's PCL/guidelines, which control the Miku layer. The source does not state a blendshape count, expression animation count, or explicit game/application embedding permission.

**Xenrya fit.** Easy to obtain and edit for a local experiment, but less evidence is available about expression quality and runtime compatibility than for Daily or Tea Chami. It is a reasonable fallback if the model's appearance is appealing after a manual preview.

### 5. Benjamin Miku — explicit app/game permission

**Creator and source.** 水浸堂01 publishes the free [BOOTH package](https://booth.pm/ja/items/3761504), titled “複製技術時代の初音ミク” / “Benjamin-MIKU.” The page links a [VRoid Hub preview](https://hub.vroid.com/characters/4999649157124891907/models/619979952187755830). The creator's contact is listed on the source page as `kimikagedou_krakatit@icloud.com`.

**Format and appearance.** The package contains `.vroid`, `.vrm`, and Blender data. The creator reports 47,271 polygons, 20 materials, and 162 bones, made with VRoid Studio 1.2.0. No facial blendshape or expression count is stated. The page describes a doll-style model, so it may read differently from Daily's compact anime look.

**Terms.** Model and texture modification, VRSNS use, use in games/apps that load VRM or VRoid files, and video/streaming are allowed. VTuber activity, R18/R18-G, commercial use, self-claiming authorship, secondary distribution, sale, and redistribution of the model or textures are prohibited. Credit is not required, but the creator welcomes an introduction. Crypton's Miku guideline takes priority.

**Xenrya fit.** This is technically attractive because the app/game case is explicit and the local noncommercial use case fits the creator terms. It is an older asset, has no published expression inventory, and its public page does not establish a modern VRM 1.0 path. Treat it as a compatibility fallback, not the primary visual choice.

### 6. RIDEREX Miku V4X — premium, highly constrained alternative

**Creator and source.** RIDEREX publishes the ¥4,900 [supporter package](https://booth.pm/ja/items/6150221) and a [VRoid Hub preview](https://hub.vroid.com/en/characters/714854075632737787/models/2344522750047250475). The source page also links the creator's [RIDEREX YouTube channel](https://www.youtube.com/@RIDEREX).

**Format and expressions.** The package includes VRM 0.0, VRM 1.0, and PMX. The creator says facial-expression additions are allowed, but does not publish a count. The model is intended for animation, doujin games, VRChat, MMD, and related work. The source warns that VRM 1.0 support is limited in some applications and that VRM 0.x is the broadly compatible option.

**Terms.** Clothing and clothing/body color changes and added expressions are allowed. The basic face shape, hairstyle, body shape, and balance may not be changed. The unmodified or modified model data may not be redistributed or sold; the source allows inclusion inside a doujin game but prohibits ordinary commercial use, limiting monetization to doujin scale. NFT, AI-training, religious/political, harassment, and self-authorship uses are prohibited. Credit must use `Model:RIDEREX式 初音ミクV4X` or `Model:RIDEREX式 初音ミクV4X改変`; linking the creator is requested but not mandatory. Crypton's guideline controls if it is stricter.

**Xenrya fit.** Visually promising and available in both VRM generations, but the price and shape restrictions make it a poor first Phase 0 fixture. It is suitable only as a private user-selected pack after Xenrya can load VRM reliably and display the required credit locally.

## Clear exclusions and conditional leads

These were not ranked as practical Xenrya choices because a required term is missing or the public terms make the intended integration a poor fit:

- [16th Anniversary Dear Creators Miku](https://piapro.jp/t/esB3), by 幻特白鷺, has a [Niconico 3D preview](https://3d.nicovideo.jp/works/td89577) and official Piapro hosting. The page says “MMD + VRM,” noncommercial, and original license, but the exact archive/readme license, expression inventory, modification rights, and redistribution rights were not verified without downloading. Keep it conditional until those terms are read.
- [ROLOCK Miku](https://booth.pm/ja/items/6690538) has a [VRoid Hub preview](https://hub.vroid.com/en/characters/4564846730437883271/models/4501571899719145812), but the BOOTH page only points to Crypton's guidelines and does not state creator-specific modification, attribution, public-display, redistribution, or commercial terms. Ask the creator before embedding or modifying it.
- [Tiny Miku](https://piapro.jp/t/PPva), by ユーリ, has VRM + FBX but Piapro explicitly marks it noncommercial and “do not modify.” It is not suitable for a reaction-driven companion.
- The previously researched [MW Miku](https://booth.pm/en/items/6290737) is free and well documented, but it prohibits all modification and commercial/profit-seeking use. It remains a no-edit private fallback, not a Daily replacement.
- The previously researched [Dahlia Miku V4X](https://hub.vroid.com/en/characters/7032412562763742257/models/8129529860751927903) allows alteration but prohibits commercial, corporate, sexual, and redistribution use and requires attribution. It is still viable for a private unmodified/locally adjusted test, but its page does not state game/app integration or expression coverage, so it ranks below the candidates above.

## Integration contract for any local candidate

Use an opt-in path outside the repository, for example:

```text
~/.local/share/xenrya/local-characters/miku/
```

The directory should contain the model and a locally written `NOTICE.md` with the source URL, creator, retrieval date, exact terms URL, PCL URL, and required attribution. The path must be absent from clean checkouts and disabled in CI, smoke tests, release packaging, crash reports, screenshots, recordings, issues, and pull requests. Keep converted VRM files, rendered PNGs, animation caches, and shader caches outside the repository too.

For Phase 0, retain an original/CC0 public fixture. Treat the local Miku pack as a user-specific integration path, not as Xenrya's bundled character. The first adapter should target VRM 0.x, because Daily, Tea Chami's Hub preview, rurune's Hub metadata, Imayahaya, and the broader VRM tooling ecosystem expose 0.x compatibility more consistently than VRM 1.0.

This is a source-and-terms comparison, not legal clearance. If Xenrya later distributes a model, shows it in public demos, or ships a service using it, re-check both the creator's current terms and Crypton's current rules.
